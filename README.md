# ⚔️ Lineage 2 Epic Boss Radar & LFG Hub (Pay2KILL Alliance)

Комплексная веб-платформа для альянса **Pay2KILL** (Lineage 2 / Unreal Engine 5), объединяющая два ключевых боевых модуля:
1. **Эпик Радар Боссов (Boss Radar)** — круглосуточный мониторинг таймеров респауна боссов (20–56 ур. и эпиков), координация дежурств скаутов на спотах, распределение камерных окон и мгновенное оповещение Командного Канала (CC) сиреной при появлении босса.
2. **Поиск Группы (LFG Hub)** — формирование конст-партий (CP) и рандом-групп, живая очередь игроков по архетипам (Танки, Маги, Луки, Саппорты), база знаний сетапов и устав альянса.

## 1. Стек технологий и архитектура

| Уровень | Технологии | Назначение |
|---|---|---|
| **Frontend Framework** | **Next.js 15+ (App Router)**, React 19, TypeScript | Server Components, оптимизированный роутинг, API Routes |
| **Стилизация** | **Tailwind CSS v4**, `@tailwindcss/postcss`, `tw-animate-css` | Адаптивная темная кибер-тема Lineage 2, Glassmorphism, Neon HUD |
| **Иконки и анимации** | `lucide-react`, `motion` (Motion 12) | Векторные индикаторы классов, плавные переходы |
| **Стейт-менеджмент** | **Zustand 5** | Реактивные хранилища данных на клиенте с авто-поллингом |
| **Realtime-связь** | Web `BroadcastChannel` API | Нулевая задержка уведомлений между открытыми вкладками браузера |
| **Базы данных** | Dual-Disk JSON Storage (`fs`) + **Google Cloud Firebase Firestore** | Надежное долговременное хранение состояния боссов, LFG и учетных записей |
| **Звуковое ядро** | Web Audio API (`audio-alerts.ts`) | Синтез тревожных сирен, радио-готовности и тактических сигналов |

## 3. Логика синхронизации данных

Архитектура обеспечивает консистентность данных между множеством одновременно подключенных мемберов альянса без задержек и гонок данных.

### 3.1. REST API бэкенда

Вся синхронизация выполняется через Next.js Route Handlers (`app/api/*`):

#### `/api/bosses`
- **`GET`**: Возвращает полное актуальное состояние (`bosses`, `spectators`, `accountOccupancies`, `spawnAlertLogs`).
- **`POST`**: Принимает команды:
  - `heartbeat`: Пинг присутствия пользователя на трибуне наблюдателей (с авто-удалением неактивных через 60 сек).
  - `set_tod_now`: Запись времени убийства босса (`todTimestamp`). Сервер автоматически рассчитывает точные временные метки открытия окна (`windowStartTimestamp`) и закрытия окна (`windowEndTimestamp`) на основе индивидуального кулдауна босса.
  - `set_tod_custom`: Ручной ввод точного времени смерти (для синхронизации с логами сервера L2).
  - `reset_boss`: Сброс статуса босса в режим ожидания.
  - `occupy_spot` / `leave_spot`: Занятие спота скаутом (с указанием ника, клана и класса дежурного).
  - `trigger_spawn_alert` / `cancel_spawn_alert`: Отправка общекланового алерта о респе босса в лог и триггер сирены.
  - `trigger_ready_check` / `confirm_ready_check`: Проверка боеготовности дежурного на точке (радио-сигнал).
  - `occupy_account` / `release_account`: Бронирование общего камерного аккаунта.

#### `/api/lfg`
- **`GET`**: Возвращает списки активных очередей игроков, пати, кланов и топиков базы знаний.
- **`POST`**: Обрабатывает действия: `join_queue`, `leave_queue`, `create_group`, `join_group`, `disband_group`, `assign_slot`, `kick_member`, `update_charter`.

#### `/api/auth`
- **`POST`**:
  - `login` — проверка пары логин/пароль, генерация защищенного сессионного токена, обновление времени последней активности.
  - `register` — создание учетной записи с привязкой мейн-персонажа и выдачей базовых прав.
  - `verify_session` — валидация сессионного токена при перезагрузке страницы.
  - `get_all_users` — получение списка всех мемберов с их активностью (только для роли с `canManageUsers`).
  - `update_user_permissions` — моментальное обновление прав мембера через чекбоксы в админке.
  - `delete_user` — удаление учетной записи (только администратором).

### 3.2. BroadcastChannel (межвкладочная синхронизация)

Для устранения задержек между открытыми вкладками одного браузера используется канал:
```typescript
const channel = new BroadcastChannel('p2k_boss_tracker_alerts_v1');
```

События канала:
- `SPAWN_ALERT` — немедленный запуск боевой сирены и показ всплывающего алерта на всех открытых вкладках.
- `SPAWN_ALERT_CANCEL` — мгновенное выключение сирены при отмене тревоги.
- `READY_CHECK_TRIGGERED` — звуковой сигнал готовности споттеру.
- `READY_CHECK_CONFIRMED` — остановка сигнала готовности после подтверждения споттером.
- `FORCE_LOGOUT_ALL` — принудительный сброс сессий по команде КЛа.

### 3.3. Персистентность и отказоустойчивость (Dual-Disk Storage)

Для защиты от сброса состояния при перезапуске Node.js процессов реализован двухуровневый механизм персистентности:
1. **Основное хранилище**: директория `data/*.json` в корне проекта (`users.json`, `boss-state.json`, `lfg-state.json`).
2. **Аварийный бэкап**: параллельная запись в системный `/tmp/*.json` (`p2k_users.json`, `boss-state.json`, `lfg-state.json`).

При старте бэкенд проверяет наличие файлов в `data/`, а при их отсутствии автоматически восстанавливает актуальное состояние из резервной копии в `/tmp/`.

## 4. Система пользователей и матрица ролей

Система доступа полностью очищена от устаревших одноразовых PIN-кодов. Реализована классическая безопасная модель учетных записей с гранулярными правами доступа.

### 4.1. Авторизация и сессии

- Пользователь регистрируется с уникальным логином, паролем, игровым никнеймом и кланом.
- Сессионный токен сохраняется в `localStorage` по ключу `tl_user_session_v2`.
- При открытии сайта токен автоматически верифицируется через `/api/auth` (действие `verify_session`), обновляя права доступа.

---

### 4.2. Гранулярные права (Permissions Matrix)

В интерфейсе администратора (`AdminRolesModal.tsx`) для каждого мембера доступны 5 независимых переключателей:

| Разрешение | Код в системе | Возможности пользователя |
|---|---|---|
| 👑 **Управление правами** | `canManageUsers` | Доступ к админ-панели мемберов, просмотр статусов онлайн, изменение прав и удаление пользователей. |
| ⏱️ **Таймеры боссов** | `canEditBosses` | Установка времени смерти боссов (TOD), ручной ввод часов/минут, сброс таймеров, подтверждение дежурств. |
| 👁️ **Просмотр боссов** | `canViewBosses` | Доступ к экрану радара боссов, просмотр статусов и таймеров, трибуна наблюдателей. |
| 👥 **Управление LFG** | `canManageLfg` | Создание партий, редактирование требований, роспуск групп, исключение игроков из КП. |
| 📋 **Просмотр LFG** | `canViewLfg` | Просмотр списка групп и очереди игроков, подача личной заявки в поиск. |

Автоматическое вычисление роли:
- Пользователь с `canManageUsers = true` получает статус **Admin (КЛ)**.
- Пользователь с `canEditBosses = true` получает статус **Scout (Скаут)**.
- Пользователь с базовыми правами просмотра получает статус **Member / Viewer**.

- **Node.js**: версия 18.18.0 или выше (рекомендуется LTS 20.x).

## 6. Восстановление данных и Disaster Recovery

### Создание резервной копии данных
Все текущие данные состояния (боссы, дежурства, аккаунты, очереди LFG, пользователи) находятся в папке `data/`:
```bash
tar -czvf backup_p2k_$(date +%F).tar.gz data/
```

### Восстановление из бэкапа
В случае повреждения файлов данных:
1. Остановите процесс Node.js:
   ```bash
   killall -9 node
   ```
2. Распакуйте архив с резервной копией в корень проекта:
   ```bash
   tar -xzvf backup_p2k_YYYY-MM-DD.tar.gz
   ```
3. Запустите сервер заново:
   ```bash
   npm run start
   ```

### Экстренный сброс пароля администратора
Если доступ к аккаунту КЛа утерян:
1. Откройте файл `data/users.json` в текстовом редакторе.
2. Найдите объект пользователя с логином `"username": "muson"`.
3. Установите поле `"passwordHash"` на хеш нового пароля или временно удалите `data/users.json` и `/tmp/p2k_users.json` — при следующем запросе сервер пересоздаст дефолтного администратора `muson` / `admin1234`.
